# Spec: API Integrations (F5)

> Version: v1.2  
> Status: Design  
> Dependencies: v1.0 (Cases, Log Sources), `cryptography` package

---

## Problem Statement

TinySIEM currently only ingests logs pushed to it via `POST /ingest/raw` or `POST /ingest/file`. Security teams using SaaS tools (AWS CloudTrail, Google Workspace) have no way to pull logs from those platforms without building their own shippers. API Integrations adds pull-based pollers: each integration is configured once in the UI, stores encrypted credentials, and runs on a schedule to pull and ingest events automatically.

---

## Design Principles

1. **One Python file + one YAML config per integration.** New integrations are drop-in additions with no framework changes.
2. **Credentials never leave the server unmasked.** After initial save, the API only returns the last 4 characters of any credential field. The stored value is Fernet-encrypted at rest.
3. **Pull, not push.** All integrations are pollers that call third-party APIs on a schedule.
4. **Failures are observable, not silent.** Each poll run records its outcome in `integration_runs`. The UI shows health.

---

## Credential Encryption

Credentials are encrypted using `cryptography.fernet.Fernet` (AES-128-CBC + HMAC-SHA256). The master key is stored in `TINYSIEM_MASTER_KEY` env var — a 32-byte URL-safe base64-encoded key generated at setup time.

**Generate a master key:**
```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

This value goes in `.env` as `TINYSIEM_MASTER_KEY`. The container will not start without it (validated at startup alongside `TINYSIEM_API_KEY` and `TINYSIEM_JWT_SECRET`).

**Encryption helper (`app/crypto.py`):**
```python
from cryptography.fernet import Fernet
from app.config import settings

def encrypt(plaintext: str) -> str:
    return Fernet(settings.master_key.encode()).encrypt(plaintext.encode()).decode()

def decrypt(ciphertext: str) -> str:
    return Fernet(settings.master_key.encode()).decrypt(ciphertext.encode()).decode()
```

## Data Model

### New Table: `integrations`

```sql
CREATE TABLE IF NOT EXISTS integrations (
    integration_id  VARCHAR PRIMARY KEY,
    name            VARCHAR NOT NULL UNIQUE,   -- user-given display name
    integration_type VARCHAR NOT NULL,         -- "aws_cloudtrail" | "google_workspace"
    enabled         BOOLEAN NOT NULL DEFAULT TRUE,
    config          JSON NOT NULL,             -- non-sensitive config (region, bucket, etc.)
    credentials     JSON NOT NULL,             -- Fernet-encrypted JSON blob
    schedule_minutes INTEGER NOT NULL DEFAULT 15,
    created_by      VARCHAR NOT NULL,
    created_at      TIMESTAMP NOT NULL,
    updated_at      TIMESTAMP NOT NULL,
    last_run_at     TIMESTAMP,
    last_run_status VARCHAR                    -- "ok" | "error" | null
);
```

`credentials` is stored as a JSON blob where every value is a Fernet-encrypted string:

```json
{
  "aws_access_key_id": "<encrypted>",
  "aws_secret_access_key": "<encrypted>"
}
```

This allows multi-field credential sets without a fixed column schema.

### New Table: `integration_runs`

```sql
CREATE TABLE IF NOT EXISTS integration_runs (
    run_id          VARCHAR PRIMARY KEY,
    integration_id  VARCHAR NOT NULL,
    started_at      TIMESTAMP NOT NULL,
    finished_at     TIMESTAMP,
    status          VARCHAR NOT NULL,          -- "running" | "ok" | "error"
    events_pulled   INTEGER NOT NULL DEFAULT 0,
    events_ingested INTEGER NOT NULL DEFAULT 0,
    error_message   VARCHAR,
    next_cursor     VARCHAR                    -- pagination cursor / last timestamp for next poll
);

CREATE INDEX IF NOT EXISTS idx_ir_integration ON integration_runs(integration_id);
CREATE INDEX IF NOT EXISTS idx_ir_started     ON integration_runs(started_at);
```

`next_cursor` stores the last-fetched timestamp or API cursor so the next poll continues where the previous one left off. Stored as a string; interpreted by each integration's driver.

## Integration Driver Interface

Each integration is implemented as a Python class conforming to a simple protocol:

```python
class IntegrationDriver(Protocol):
    integration_type: str              # "aws_cloudtrail"
    display_name: str                  # "AWS CloudTrail"
    credential_fields: list[str]       # ["aws_access_key_id", "aws_secret_access_key"]
    config_fields: list[str]           # ["region", "s3_bucket"]

    async def pull(
        self,
        config: dict,
        credentials: dict,             # already decrypted by the runner
        cursor: str | None,            # last cursor from previous run
    ) -> tuple[list[dict], str | None]:
        """
        Returns (events, next_cursor).
        Each event is a dict with 'source' and 'raw' keys,
        formatted for POST /ingest/raw.
        """
        ...
```

### Built-in drivers

#### `app/integrations/drivers/aws_cloudtrail.py`

- **Auth:** AWS access key + secret (stored encrypted) or IAM role (no credentials needed; uses instance metadata)
- **Config fields:** `region`, `s3_bucket` (if using S3 delivery), `log_group` (if using CloudWatch Logs)
- **Pull method:** reads from S3 (list objects since last cursor, download and parse GZIP JSON) or CloudWatch Logs (`filter_log_events` with `startTime` from cursor)
- **Source name emitted:** `aws_cloudtrail`
- **Requires:** `boto3` >= 1.34

#### `app/integrations/drivers/google_workspace.py`

- **Auth:** service account JSON key (stored encrypted as a single multi-line JSON blob)
- **Config fields:** `admin_email` (impersonated user), `application_name` (`login`, `admin`, `drive`, etc.)
- **Pull method:** Google Reports API (`activities.list`) with `startTime` cursor
- **Source name emitted:** `google_workspace_{application_name}`
- **Requires:** `google-api-python-client` >= 2.120, `google-auth` >= 2.28

## Scheduler

The integration scheduler runs as an `asyncio` background task (same pattern as the baseline job). It wakes every 60 seconds and checks which enabled integrations are due to run (based on `last_run_at + schedule_minutes`).

```python
async def _integration_loop():
    while True:
        await integration_runner.run_due()
        await asyncio.sleep(60)
```

`run_due()` checks all enabled integrations and dispatches each due integration as a coroutine. Integrations run sequentially (not in parallel) in the scheduler loop to avoid concurrent DuckDB writes from multiple integrations.

## API Design

Base path: `/integrations`  
Auth: admin role required for all write operations. Analyst can read.

### `GET /integrations`

List all integrations with health status.

**Response:**
```json
{
  "integrations": [{
    "integration_id": "uuid",
    "name": "prod-cloudtrail",
    "integration_type": "aws_cloudtrail",
    "enabled": true,
    "schedule_minutes": 15,
    "last_run_at": "2026-06-29T10:30:00",
    "last_run_status": "ok",
    "events_pulled_last_run": 143,
    "created_by": "admin",
    "created_at": "2026-06-01T00:00:00"
  }]
}
```

Note: no `credentials` or `config` fields in list response.

### `POST /integrations`

Create a new integration.

**Request:**
```json
{
  "name": "prod-cloudtrail",
  "integration_type": "aws_cloudtrail",
  "schedule_minutes": 15,
  "config": {
    "region": "us-east-1",
    "s3_bucket": "my-cloudtrail-bucket"
  },
  "credentials": {
    "aws_access_key_id": "AKIA...",
    "aws_secret_access_key": "secret..."
  }
}
```

Server encrypts each value in `credentials` before storing. Returns `201` with the created integration (credentials masked).

### `GET /integrations/{integration_id}`

Full integration config. `config` is returned in full. `credentials` is returned masked (last 4 chars of each value, rest replaced with `*`).

**Response (credentials masked):**
```json
{
  "credentials": {
    "aws_access_key_id": "**...KIVA",
    "aws_secret_access_key": "**...x9Kz"
  }
}
```

### `PATCH /integrations/{integration_id}`

Update integration. If `credentials` object is included, re-encrypts and replaces all credential fields.

### `DELETE /integrations/{integration_id}`

Hard-delete integration and all its run history. Audit logged.

### `POST /integrations/{integration_id}/run`

Trigger an immediate poll (runs in background). Returns `202 Accepted` with `run_id`.

### `GET /integrations/{integration_id}/runs`

List recent run history.

**Query params:** `limit` (default 20), `status` filter.

**Response:**
```json
{
  "runs": [{
    "run_id": "uuid",
    "started_at": "2026-06-29T10:30:00",
    "finished_at": "2026-06-29T10:30:45",
    "status": "ok",
    "events_pulled": 143,
    "events_ingested": 143,
    "error_message": null
  }]
}
```

### `GET /integrations/types`

Returns available integration types and their required fields (for building the creation form dynamically).

**Response:**
```json
{
  "types": [{
    "integration_type": "aws_cloudtrail",
    "display_name": "AWS CloudTrail",
    "credential_fields": ["aws_access_key_id", "aws_secret_access_key"],
    "config_fields": ["region", "s3_bucket"]
  }]
}
```

**"+ New Integration" flow:**
1. Select type from dropdown (dynamically from `GET /integrations/types`)
2. Form fields appear: name, schedule_minutes, config fields, credential fields (password inputs)
3. Credential fields never shown again after save — display masked values on edit

**Integration detail (row expand):**
- Last 5 run history with status, events pulled, duration, error message
- "Run Now" button → `POST /integrations/{id}/run` → shows spinner then refreshes
- "Edit" button → opens credential re-entry form (all credential fields required on edit)
- "Disable/Enable" toggle

## Security Notes

- Credential fields are encrypted before writing to DuckDB. Even if the database file is exfiltrated, credentials are unreadable without `TINYSIEM_MASTER_KEY`.
- Master key rotation is manual: re-encrypt all credential rows with the new key, then update `TINYSIEM_MASTER_KEY`. A utility script for this will be provided when the feature is implemented.
- Integration runs execute in the same process as the API. A buggy driver cannot crash the API server but can block the integration loop for its run duration. Timeouts (30s per poll) are enforced with `asyncio.wait_for`.
- Credentials are decrypted only in memory for the duration of a poll run. They are never written to logs, audit detail, or error messages.

---

## Out of Scope

- Webhook-based ingest from integration platforms (Splunk HEC, Datadog Forwarder)
- Two-way integration (writing back to third-party platforms)
- OAuth flow for integrations (service account / API key only in v1.2)
- More than 2 built-in drivers in v1.2 (AWS CloudTrail + Google Workspace)
- Rate limit handling beyond basic retry-with-backoff
